# SW-A00 — Software Track Plan & Tooling Map

**Weight:** 5% · **Due:** After SW welcome · **Module:** sw-00-welcome

## Prompt

Show you understand the **software track path** and the **program vs CISS lab** tooling split before you start coding labs.

## Deliverables

1. **Personal track plan** (½–1 page): which modules you will complete and in what order; one risk (tooling, time, access) and a mitigation.
2. **Tooling map table** — for each role (ticket, Git host, review, CI, artifacts, runtime), list **program (work)** vs **CISS lab** tools.
3. **Three SE links** — one sentence each connecting software craft to requirements, interfaces, and verification.
4. **Language note** (5–8 lines): you are probably stronger in Python — how you will use it as a *scratch* aid without substituting it for **Java** deliverables; one sentence on why the contract wants Java.  
5. **Integrity note** — how you will cite AI help and keep commit history honest (3–5 bullets).

## Quality bar

- Program vs CISS tools are not mixed up.
- Plan is realistic for an intern week cadence.
- SE links are specific, not “software is important.”

## Rubric

| Dimension | Max | What we look for |
|-----------|-----|------------------|
| completeness | 10 | Plan + tooling table + SE links + language + integrity |
| accuracy | 10 | Correct program vs lab mapping |
| communication | 5 | Clear enough for a peer to follow |
