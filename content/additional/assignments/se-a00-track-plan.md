# SE-A00 — SE Track Plan & Artifact Map

**Weight:** 3% · **Due:** Week 1 Thursday · **Module:** se-00 Welcome  
**Cadence:** Assigned Monday after kickoff. Work Monday–Wednesday. Due Thursday Q&A.

## Prompt

Show you understand **why this course exists**, the **derivation chain**, and the **Monday / Thursday rhythm** before you write any shall-statements.

## Deliverables

1. **Personal track plan** (½ page): which SE modules you will complete and in what order; one risk (time, English, tooling, ops background) and a mitigation.
2. **Artifact map table** — for each layer below, name the artifact, the typical tool you will use, and the next module that deepens it:

   | Layer | Artifact I will produce | Simplest tool | Module |
   |-------|-------------------------|---------------|--------|
   | Vision | | | se-02 |
   | Needs | | | se-02 |
   | Use cases | | | se-03 |
   | Requirements (EARS) | | | se-04 |
   | Architecture | | | se-05 |
   | Behavior | | | se-06 |
   | ICD | | | se-07 |
   | RTM / V&V | | | se-08 |

3. **Design-first trap (5–8 lines):** describe one time you (or a team you know) jumped to a solution. Which course layer was skipped?
4. **Integrity note** — 3–5 bullets: how you will cite AI, keep work your own, and use Thursday Q&A.

## Quality bar

- Chain order is Vision → Needs → Use cases → Requirements (not “requirements then vision”).
- Tools are simple and reviewable (markdown, tables, Mermaid) — not a shopping list of enterprise licenses.
- Risk/mitigation is specific to *you*, not a slogan.

|-----------|-----|------------------|

| accuracy | 10 | Correct chain order and module mapping |
